# 接口文档 v5

本规则定义前端消费的接口正文；范围确认、代码对账和冲突回流由[接口文档 skill](../skills/backend/06-interface-document.md#workflow)执行。它是调用契约，不是测试、审批或服务版本证明。

## 文档结构

在项目 Harness 的接口文档目录只生成 `api-document.md`，协议为 v5。第一章「接口总览」必须逐 API 列出：接口编号、来源 Plan、接口地址、接口名称；不得使用 API 范围合并行。第二章「具体接口」中每个端点使用 `### [API-NNN] 名称`，固定包含「来源 Plan」「接口地址」「功能说明」「请求体」「响应体」「JSON 示例」「成功状态」「错误状态」。除标题、元信息和这两章外，不生成公共模型、模块索引、记录索引或其他章节。

不展示请求模型名称。每个端点在其「请求体」表中逐字段、逐行列出直接字段、继承字段、嵌套对象、数组元素以及 path/query/form 字段；一行只能有一个字段，表列固定为「字段、类型、是否必填、说明」。即使实现复用 DTO 或字段完全相同也不得引用公共请求模型。响应体表列固定为「字段、类型、说明」，同样一行只写一个 `data` 字段；分页元素、固定键 Map、动态键 Map、空 data 和文件流均不得省略。禁止用“字段见公共模型”“包含摘要”“分页结果”等文字代替字段定义。

每个接口必须提供一个 `json` 代码块作为 JSON 样式示例，同时展示请求和响应包装；示例字段必须来自本接口的字段表，只使用虚构值，且不替代字段表。成功状态表固定写「HTTP 状态、业务状态、说明」；错误状态表固定写「触发条件、HTTP / 业务码、说明」。接口无请求体、空 `data`、文件流和动态键响应仍必须保留四张表。文档只呈现统一后的接口定义，不记录阻塞、阶段状态、revision、SHA256 或 LocalTest 结论。

## 字段与特殊响应

- 字段路径以 JSON 负载为准：根包装使用 `data`，嵌套对象使用 `data.items[].field`；path/query/header/form 字段写真实传输名称。类型采用 string/integer/number/boolean/array/object/file/binary，并在说明中写枚举、格式、默认值、可空和条件约束。不得展示或引用请求模型；响应字段也不得跳转到公共模型。
- `Map` 响应不得以 `Object`、`键值对`或“聚合结果”收尾；固定键逐项列出，动态键必须声明键模式、键的含义和 value 类型。没有可稳定描述的响应形状时，回流实现改为 DTO/VO 后再发布。
- `ResponseResult<Void>` 等空数据响应在成功响应表中写 `data` 为 `null`；下载接口写 HTTP 响应体、Content-Type 和 Content-Disposition；禁止省略成功响应表。

Controller 核实方法、完整路径、参数位置和文件流；DTO/VO 展开继承、嵌套对象和数组元素；Map/Object 从固定键写入处核实稳定键和值类型。分页写实际请求页码字段、页大小和响应字段，不能假定 `pageNo/current` 映射。枚举、默认值、可空性和条件必填写入字段表。

## 变更与边界

每个接口区分 `新增`、`编辑`、`删除`或`无 HTTP 变化`；编辑写明前后差异，删除写明替代接口、兼容期限或明确无替代。

- 不复制 SQL、Mapper、部署、账号、Token、内部 URI 或脱敏 HTTP 样例；这些属于 Exec 或 LocalTest 证据，不属于前端接口正文。
- 没有 HTTP 接口变化的 Plan 不生成具体接口；不得伪造接口。
- 前端消费点未知时写 `待前端绑定` 并保留 Plan 来源，不将其写为接口阻塞状态。
