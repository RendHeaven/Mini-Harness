# 文档时间规范

## 范围与格式

适用于 product、ui、frontend、frontend-mock、backend、TestHub 各阶段创建、更新的全部 Markdown spec 产物，包括总览、模块计划、TASK/Exec、TDD、接口测试、接口文档、Review、外部变更记录、待配置清单、测试养料、影响分析、测试设计、覆盖矩阵、用例和生成/同步报告。无独立模板的产物也必须遵守。

- 文档时间统一为 `yyyy-MM-dd HH:mm:ss`（24 小时制、各部分补零），例如 `2026-09-09 14:05:03`；文档明确写入 `时区：Asia/Shanghai`。
- 写入时读取真实系统时钟并转换为 Asia/Shanghai；不得凭会话日期猜测时分秒。Python 格式串为 `%Y-%m-%d %H:%M:%S`，dayjs 格式串为 `YYYY-MM-DD HH:mm:ss`。
- 本规则约束文档生命周期和操作记录，不改变业务字段、确认日期、Manifest/Execution Schema 或 JSON/API 协议。远端回执原始时间保留；在文档中展示生成、分析、验证或同步时间时转换为上述格式。

## 创建与编辑

1. 首次生成时记录“创建时间”“最后编辑时间”“时区”和“编辑记录”。首次创建的两项时间相同，编辑记录保留真实创建操作。
2. 后续每次修改、补充、重生成或追加文档时保留创建时间，更新最后编辑时间，并在编辑记录末尾追加 `时间｜操作｜摘要`。同一次连续编辑保存可合并一条操作记录；后续独立操作不得覆盖上一条。
3. 追加 TDD、Exec、Review 或外部变更时，既更新文档级时间，也为具体追加行或记录块写入编辑时间。既有追写表的“编辑时间”、前端 Exec 追写标题均精确到秒；无时间列的记录块添加 `编辑时间` 字段。不得用文档最后编辑时间替代逐条操作时间。
4. 首次生成后的创建时间不可改写，既有编辑记录不得覆盖或删除。复制、重命名、checkout、重新生成同一逻辑文档均不重置创建时间。
5. 无实质修改时不刷新时间。最后编辑时间不得早于创建时间，新增编辑记录按实际发生顺序追加。

## 现有文档与特殊结构

- 不批量改写历史周期。当前文档下次编辑时补齐元数据；历史创建时间只能引用可信的原始文档或审计记录，并说明依据。无法确认时写 `未知（历史未记录）`，不得将 Git 首次提交、文件系统创建时间或当前时刻直接冒充原始创建时间。
- 旧追写只有日期时保留原值，不补造 `00:00:00`；本次及后续操作必须使用真实秒级时间。
- TestHub `cases.md` 将全部时间元数据和文档编辑记录放在 `## 文档信息` 内；不得改变 13 列导入表或新增会被识别为用例的三级标题。完整重生成仍保留稳定文档身份、创建时间与编辑历史。
- 待外部配置清单的编辑记录仅描述本次清单操作（新增、修改、移除及关联记录路径），不扩展为已完成事项表或阶段盘点。
- 生成报告、同步报告等无独立模板的文件沿用相同元数据。机器 JSON 回执不添加这些 Markdown 字段。

Gate 与机器修订索引使用秒级 ISO 8601 +08:00；Markdown 可使用 YYYY-MM-DD HH:mm:ss 并注明 Asia/Shanghai。所有时间读取真实时钟。
