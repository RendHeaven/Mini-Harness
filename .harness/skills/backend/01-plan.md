# Java 后端 Plan

## Objective

把 PRD 与真实工程转成可评审的 Java 后端方案：范围、受影响链路、接口或任务语义、技术取舍、风险、业务验收与可执行任务。本阶段不产生外部系统设计、测试设计、实际执行安排或业务代码。

## Inputs

- 产物相对[工作流](../../workflow/backend-workflow.md#阶段执行)指定的阶段根。
- 文档遵循[时间规范](../../rules/document-timestamps.md)。
- 必需需求源：当前 PRD 和项目根原型仓库，固定 backend.sources；其他角色 Gate 不是前置。

- 必需：当前 PRD、`execution.yaml`、服务目录、目标服务 AGENTS/上下文、源码、表结构、历史需求和历史研发产物。
- 可选：Dev Guide、UI Handoff；存在时仅用于交叉核对，缺失或过期不得阻塞后端研发。
- 产品范围、流程、字段、权限、业务规则、异常或验收不清时先记录并询问用户按哪个角色处理；代码、数据、依赖证据不足或仍需负责人决定时标记 `blocked`。

## Workflow

1. 对全部 `REQ-*` 声明适用性，明确范围、非目标、角色、受影响服务和调用方；来源不完整的业务语义登记 `DEC-*`，询问用户角色归属，不在 Plan 静默补全或自动切换。
2. 按业务边界和独立交付风险划分单模块或多模块；跨模块能力指定唯一责任 Plan，其他模块仅引用其任务或决策。
3. 沿受影响链路调研历史产物、代码、接口、调用方和相关数据对象，记录可复用设计、兼容影响及证据。仅当存在性能影响或数据变更时，核对数据量、索引及适用的 `EXPLAIN`；不执行写操作。
4. 为每个责任模块完成业务流程、接口或任务语义、数据影响、技术取舍、风险和业务验收。需要架构、DBA、运维或安全 Owner 取舍的事项登记 `TDEC-*`，未确认的关联任务保持 `blocked`。
5. 用模板产出 Plan；模板和校验器负责 TASK ID、HTTP/定时任务映射、字段完整性、单/多模块文件布局与 `ready` 判定。

## Decision rules

- Plan 写接口路径、方法、角色/权限、字段名与位置、必填性、业务语义/约束、响应语义、错误场景和副作用；Java 类型、校验注解、真实错误包装和实测样例由 TDD 基于真实工程补全。
- 产品语义以 `PRD/DEC` 追溯，工程现状以代码、数据库或配置证据追溯，技术取舍才引用 `TDEC`；三者不可互相替代。
- Plan 的验收是业务结果与关键约束，不展开正常、边界、异常、权限的测试用例；测试设计由 TDD 和后续测试阶段完成。
- SQL、Nacos、定时任务、权限、对象存储、消息与外部客户端的详细设计统一交由 `02-external-design.md`；Plan 仅指出触发条件、业务影响和责任任务。
- 调研事实不清时保持 `blocked`，不得编造源码、表结构、接口或调用方；“候选”“TDD 定稿”“后续确认”不是关闭决策的证据。
- 生产写操作、DDL 执行、数据迁移或外部状态变化不因本 Skill 获得授权。

## Output contract

- 输出 `1-plan/plan-overview.md`；多模块增加 `plan-NN-{slug}.md`。总览只保留 REQ 映射、模块索引和跨模块依赖，详情只保留本模块方案。
- 范围、受影响链路、接口或任务语义、技术取舍、风险、业务验收和待确认事项真实可追溯时，按模板规则标记状态；否则保持 `draft|blocked`。
