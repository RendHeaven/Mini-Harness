# Java 后端独立 Review

## Objective

独立核对 Plan、TDD、Exec、结构化接口文档、接口测试和代码，形成可定位、可修复、可复测的发现。

## Inputs

- 产物相对[工作流](../../workflow/backend-workflow.md#阶段执行)指定的阶段根。
- 文件编号、总览与详情分工、追写及后端 TASK 状态遵循[后端交付规则](../../rules/backend-delivery.md)。
- 文档遵循[时间规范](../../rules/document-timestamps.md)。
- 当前来源哈希、所有后端阶段产物、代码 diff/revision、测试和结构化接口文档。
- 输入证据缺失或 revision 不一致时记录告警并在真实可见范围内审查，不补造证据，也不阻止 Review 检查完成。

## Workflow

1. 按后端交付规则建立 Review 总览，核对已开始模块的输入与全局风险索引。
2. 在已开始模块的 Review 中建立接口、服务、表、调用方、配置、外部依赖和风险索引。
3. 在模块 Review 中检查设计、分层、复杂度、事务、并发、权限、安全、错误和可观测性；核对接口文档与 Plan、TDD、Exec、真实代码的一致性。
4. 对模块涉及的复杂 SQL 核对真实语句、参数、EXPLAIN、索引和锁风险。
5. 按 P0/P1/P2 将发现写入所属模块；跨模块发现仅在总览维护索引，并链接所有受影响模块。
6. 在模块 REQ 覆盖表中逐项关联该 Plan 的 applicable REQ 与真实代码、测试、接口或发现证据；总览聚合全部 REQ、模块状态、测试盲区和阶段结论。
7. 修复后按交付规则追写原模块的复测记录，并同步总览状态与发现索引。

## Decision rules

- P0/P1 未修复或未由真实负责人接受风险时保留真实状态并告警，不伪造接受风险；Review 检查仍完成并允许后续阶段继续。
- Review 不静默修改产品事实、UI 或结构化接口文档。
- 修复改变接口行为时必须重跑接口测试和接口文档阶段。
- 已确认 `backend n/a` 的模块仍保留同编号记录，写明无独立后端实现审查范围与外部责任方。

## Output contract

输出后端交付规则指定的 Review 总览和模块记录。REQ 覆盖、高优问题或回归检查未满足时保留真实结论并告警，Review 检查仍完成并允许后续阶段继续。
