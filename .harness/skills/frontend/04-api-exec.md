# 前端 API 实现与联调

## Objective

按结构化接口文档实现请求与页面消费，用真实网络、测试、构建和浏览器证据证明联调结果。

## Inputs

- 产物相对[工作流](../../workflow/frontend-workflow.md#阶段执行)指定的阶段根。
- 文档遵循[时间规范](../../rules/document-timestamps.md)。
- 当前 api-plan、结构化接口文档、页面实现、目标环境、账号、允许的数据范围和 `rules/frontend-engineering.md`。展示口径见 `rules/ui-standard.md`。
- 环境、权限、必要数据不足或接口定义缺失时记录告警和真实 blocked 状态，继续不依赖缺失条件的工作；未经授权的操作不得执行，也不得伪造联调结果。
- API Plan 的逐接口对照表，以及本次所选前后端分支、源码版本和运行环境来源。旧 Plan 缺少对照表时先回补；历史日志、截图或健康检查不能替代当前环境的契约核对。

## Workflow

1. 在编码前逐项读取对照表所指的正式接口正文，确认 Owner、HTTP 方法、业务路径、参数位置和页面调用方；核实旧 service、Mock 路径和历史证据与本次输入的差异。契约定义不清时先记录阻塞与回流，不自行改写接口含义。
2. 按工程规则 §3 读取实际 request 封装、apiPrefix、baseURL、请求拦截器、环境变量读取位置、构建代理及适用的主应用代理。为本次验收涉及的每种运行场景建立请求链路记录：独立页面或主应用嵌入、启动模式、浏览器 origin、实际接管代理的进程、目标类型（网关或后端直连）、目标地址、各层增删前缀规则及其配置来源。配置不可读的环节写“未确认”，不得由注释、变量名或历史记录推断已生效。
3. 将每个调用从 service 路径表达式追到浏览器最终 URL、代理转发路径和后端业务路径。区分网关与后端直连模式，只按实际路由配置增删前缀；不得因完整 URL 与文档业务路径不同就盲目改写。主应用嵌入时核实请求实际归属，不能把子应用代理当成必经环节；本机覆盖变量必须确认代码有读取逻辑，配置变动后核实相关进程已重启。
4. 完成上述核对后，在既有 API 层按正式契约实现路径、query、body、header、响应、错误和副作用；分页按工程规则 §4，空值与 `0` 按 UI 规则 §5 与工程规则 §6。复用现有组织方式不代表沿用未经核对的旧 URL；新增调用先同步 Plan 对照表。
5. 隔离或替换产品 Mock，确保生产路径不启用 Mock 数据源。验证正常、分页/筛选、加载、空、异常、权限、重复提交和竞态；只使用已授权账号和允许的数据范围。
6. 逐接口、逐实际验收场景记录请求方法、浏览器 URL、目标环境、HTTP/业务响应与预期对比，以及可复核的网络和页面证据。直接访问后端仅作为补充，不能替代页面经过实际代理链路的验证。记录运行产物版本及核实依据；源码存在某个 Controller、构建成功或健康检查通过，都不能证明目标进程已部署该接口。
7. 按工程规则 §8 运行适用测试，完成 lint、production build 和浏览器检查。使用 `template/develop/frontend/task-exec-template.md` 记录逐接口对照、请求链路、真实验收、差异回流和最终 revision；历史证据保留原版本与日期，修复后追加当前版本的复验结果。

## Decision rules

- Mock 不能作为联调通过证据。
- 每个“TASK × 接口调用位置 × 验收场景”分别记录结论：`passed`（实现、契约与真实链路验收一致）、`unverified`（已实现但未验证）、`failed`（实测与预期不符）、`blocked`（缺少明确前置条件）。没有真实证据时不得标 passed；仅有 HTTP 200 或一个接口成功不能代表其他接口或场景通过。
- `implementation` 候选来源即使得到真实响应，也不能标为正式契约联调 passed；先由 Owner 确认并回补正式文档和 Plan。方法或路径差异、目标运行版本未确认、写操作缺少授权或测试数据时，保留具体原因与 Owner，继续不受影响的工作。
- 只有 TASK 下所有必需调用和验收场景均 passed、且相关差异已闭环时，TASK 才可标 done。已实现但未验证保留 in-progress；依赖缺失保留 blocked。不能把“可进入 Review”或构建通过解释为接口已验收。
- 接口差异记录告警并反馈 backend 更新结构化接口文档；允许继续其他可执行工作，但不得把差异静默兼容或伪造联调通过。
- 产品语义、Dev Guide 或 UI Handoff 变化先记录影响并询问用户按哪个角色处理，不自动切换或代改；当前角色中不受影响的工作可继续。

## Output contract

输出 `4-api-exec/task.md`、`exec.md`、真实代码和验证证据；未完成 TASK 或失败检查保留真实状态并告警，不阻止进入 Review 检查。

`task.md` 保存 TASK 状态并引用 `exec.md`；`exec.md` 保存来源与环境、逐接口对照、请求链路、逐接口验收和差异回流。结论分别汇总已验证通过、已实现未验证、验证失败与阻塞项，禁止仅以“联调完成”概括部分通过的结果。结构化表是执行与 Review 的核对要求，现有校验器通过不代表已自动验证 URL 与真实网络证据。
