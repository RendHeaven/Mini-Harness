# 打包产品原型

## Objective

将已有产品原型目录的内容递归打包为其同级 ZIP，供下载或流转。只生成原型的派生副本。

## Inputs

- 用户的原型打包请求，以及已有原型目录。
- 未指定目录时，读取当前项目配置的 `project.prototypeRoot`，相对项目 Harness 根解析；路径约定见[项目原型](../../rules/project-assets.md#项目原型与历史路径)。不按当前工作目录猜测，不把需求周期的 `product.root` 当作原型目录。
- 用户明确指定原型目录时使用该目录；缺少项目上下文且未指定目录、或存在多个候选时，只询问待打包目录。项目默认原型位置读取 `project.prototypeRoot`。

## Workflow

1. 确定一个已有原型目录的绝对路径。用户直接请求本技能即可进入支线，无需先执行 Mock、生成 PRD 或确认 Gate。
2. 使用实际 Atlas Core 中的[打包工具](../../tools/package_prototype.py)：

   ```powershell
   python "<Atlas Core 根>/.harness/tools/package_prototype.py" --prototype-root "<原型目录绝对路径>"
   ```

   工具仅依赖 Python 标准库；使用环境中可用的 Python 解释器替换 `python`。
3. 工具在源目录的父目录创建 `<原型目录名>.zip`；已有同名文件时自动改用 `<原型目录名>-1.zip`、`<原型目录名>-2.zip` 等未占用名称，保留旧包。
4. 递归收录全部文件与子目录，包括隐藏文件和空目录，保留相对路径及文件内容；ZIP 根直接包含 `index.html`、`assets/` 等源目录内容，不额外嵌套原型目录名。工具不读取 `.gitignore`，不自动过滤、安装依赖或执行构建。
5. 工具关闭 ZIP 后重新读取并检查 CRC。仅在命令成功且校验通过后，返回工具报告的实际 ZIP 路径、文件数和压缩包大小，并结束本支线。

## Decision rules

- 源不存在、不是目录、含符号链接或 junction 等路径重定向、文件无法读取或压缩校验失败时，如实报告失败；不跳过文件后宣称完整打包。工具清理本次失败产生的半包，不删除旧包。
- ZIP 仅写在原型目录同级；不覆盖旧包，不改变原型源文件，不修改 PRD、Manifest、Execution、Gate 或项目配置。
- 打包不触发产品反问、产品确认或其他角色流程，也不代表原型的业务验收。上传、发送或发布压缩包须有相应用户指令。

## Output contract

交付一个已通过完整性检查的同级 ZIP，提供可点击的绝对路径，并说明源目录、文件数与压缩包大小。例如源目录为 `原型仓库/`，首次输出为旁边的 `原型仓库.zip`。
