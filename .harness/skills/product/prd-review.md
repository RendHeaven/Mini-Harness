# 产品反问（grilling）

## Objective

围绕当前 PRD 的目标、边界、规则和验收逐层提问，形成与产品负责人的共同理解。提问与输出采用 [Matt Pocock 的 grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md) 形式（对照日期：2026-09-20）；保留 Atlas 产品角色和追溯边界。

## Inputs

- 当前 PRD、Discovery、项目上下文和服务目录；保留真实待确认项，不要求先清零才能开展对话。
- 需要核实实现事实时，读取相关服务的 `AGENTS.md`、上下文、契约、源码及当前 Git 状态；只查与当前决策有关的证据，不要求全服务、全 REQ 质检。
- 默认只读当前可见工作区，不拉取远端、不切换分支、不修改源码。证据不可访问时说明具体缺口，不推测事实。

## Workflow

1. 将待讨论的产品决策组织成决策树，标明哪些问题依赖其他决策或尚未取得的事实。
2. 每轮找出所有前置条件已经明确、现在无需猜测就能询问的问题，一次提出这一整组问题；逐题编号并给出推荐答案和理由。
3. 等待真实答复，再据此更新决策树。依赖本轮未决答案的问题留到后续轮次；部分答复只解决对应分支，不把遗漏或沉默当作确认。
4. 可通过文件、工具或代码查到的事实自行查证，不让用户代查。有独立查证任务和可继续的提问时，可交由子代理查证；仅依赖该事实的分支等待，其他已具备条件的问题继续询问。无法取得的证据保留为未决前提，不用推荐答案替代事实。
5. 持续更新并询问，直到所有决策分支都已讨论、没有未决前提或隐含假设。概括共同理解并请求产品负责人明确确认；确认前不按对话结论执行产品修订或实施。

## Decision rules

- 推荐答案是建议，不是用户决策；由负责人选择、补充或否定。
- 当前没有可问问题但仍有未决前提时，说明正在等待的事实或答复，不宣称会话已经完成。
- 共同理解确认本身不等于产品 Gate 通过，也不扩大后续操作授权。在产品确认阶段，交付未变时可按[产品确认技能](gate-confirm.md#workflow)同时请求共同理解与最终交付的明确确认；交付有变时先确认理解、修订，再确认最终内容。已授权的业务修订按[产品追溯规则](../../rules/product-semantics-and-traceability.md)更新 Discovery 与 PRD，开始追踪后的正文变化通过既有工具追加 `CHG-*`。
- 本技能是产品确认的内置步骤，也支持单独按需调用；触发、已有结论复用与增量追问遵循[产品确认技能](gate-confirm.md)。单独调用不进入 Gate 确认，不自动推进 Manifest phase 或 Gate；代码现状不自动覆盖 PRD 承诺。

## Output contract

每轮直接输出问题与推荐答案，采用以下形式；有多少个前置条件明确的问题就列多少个，不固定为一问：

```text
❓ **Q1** - **<问题标题>**：<问题正文，可附具体选项>

➡️ <推荐答案与理由>

---

❓ **Q2** - **<问题标题>**：<另一个前置条件已明确的问题>

➡️ <推荐答案与理由>
```

结束时在对话中概括已达成的理解，等待真实确认。默认不生成 PRD Review 文件、不分配 `PQ-*`，不要求 PRD SHA256、全服务基线或全 REQ 质检表。
