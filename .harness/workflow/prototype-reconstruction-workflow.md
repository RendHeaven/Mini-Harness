# 已有页面原型补建

## 入口与边界

用户明确选择本专项即选择 UI 原型补建支线。读取项目配置、上下文、服务目录及实际 Core；定位规则沿用 [project-execution](../rules/project-execution.md)。
本专项允许只读分析目标前端源码、路由、样式和运行页面，不要求先有 PRD 或已有原型。读源码不授权修改服务；需要新增服务 Mock 或修复启动配置时交接 [frontend-mock](frontend-mock-workflow.md)，已明确授权的角色顺序不重复询问。

目标是可编辑、可独立预览、可用本地数据演示约定交互的原型。现状来源与新需求分开，源码推断不升级为产品确认；不自动生成 PRD、确认 Gate 或发布。

## 阶段

保留 01–07 七个节点：01 固定来源和范围，02 建立工作项，03–06 按工作项循环，07 准备交付后执行必需的 open-code-review 收尾审核，再汇总最终结果。节点可单独调用；单阶段请求只执行指定节点、保存下一步建议后结束，不自行进入完整循环；单独执行07时也包含其收尾审核。

先读取 [还原协议](../rules/prototype-reconstruction.md)，在范围确定时记录 requiredChecks；默认包括结构、交互、独立运行和视觉一致性。缺少原页面时仍可验证其余项目并交付 partial，不在结束时删除视觉检查项。

| 节点 | Skill | 产物 | 完成标准 |
| --- | --- | --- | --- |
| 01 来源与范围 | [来源评估](../skills/prototype-reconstruction/01-source-assessment.md) | 来源、版本、范围、模式 | 基线唯一，缺口明确 |
| 02 页面与状态 | [状态盘点](../skills/prototype-reconstruction/02-page-state-inventory.md) | 页面—状态矩阵 | 可达页面与适用状态有依据 |
| 03 证据采集 | [采集](../skills/prototype-reconstruction/03-page-evidence-capture.md) | 截图、资源、操作证据或源码引用 | 来源与采集条件可追踪 |
| 04 还原规格 | [规格](../skills/prototype-reconstruction/04-reconstruction-spec.md) | 区域、字段、动作、数据与差异 | 事实、推断、假设分开 |
| 05 构建 | [构建](../skills/prototype-reconstruction/05-static-prototype-build.md) | 项目共用原型 | 本地可预览，约定交互可用 |
| 06 验证 | [验证](../skills/prototype-reconstruction/06-prototype-verification.md) | 分项结果、问题分类、下一动作 | 按当前证据选择通过、回流或停止；关联回归有效 |
| 07 交付与收尾审核 | [交付](../skills/prototype-reconstruction/07-prototype-handoff.md) | 入口、覆盖清单、来源映射、OCR报告 | 最终累计改动已审核，问题与覆盖缺口如实归档 |

## 工作项与循环推进

工作项以“页面或区域 × 状态”为单位，使用稳定 ID 引用 states 中的一个状态或同一行为的一组代表状态；不得为减少失败而合并掉检查项。共用导航、布局、数据和资源的依赖先登记，再按依赖选择工作项。

1. 01 建立本轮来源索引与范围，保留源码和运行页各自版本，固定必需检查、允许差异和停止上限。
2. 02 从当前范围的 states 建立 workItems；优先完整主路径及其前置项，再处理空、失败、恢复等分支。范围内新发现的状态追加到清单；范围外发现只记待办，不自动扩大目标。
3. 选择依赖满足且未通过、未停止的工作项，执行 03 → 04 → 05 → 06；证据或规格已有效时可复用，跳过的节点须注明所复用的记录及摘要。
4. 每个节点结束时保存 [记录模板](../template/ui/prototype-reconstruction.example.yaml) 中的 iterations 条目，明确下一节点、目标工作项和原因；发现问题立即按下表回流，无需等待执行到 06。
5. 06 对问题先核实再分类。只修复本轮原型范围内的实现问题；来源继承行为、证据缺口及业务取舍分别登记，不自动交给构建节点改造。
6. 当前项通过或明确停止后选择下一可运行项。被依赖阻塞的项保持 blocked；其他独立项继续。队列无可运行项时，执行 06 的全局关联回归与覆盖核对，汇总已通过、失败、未验证和停止项。
7. 全局回归发现可修复问题时重新打开受影响项，继续对应回流；没有可继续的动作后进入07，整理交付资料并对本轮最终累计原型变更执行open-code-review。06中的提前审核不能替代这次收尾审核。核实问题后按原路由返工，经06回归后重新进入07复核；满足所有条件才结束，队列为空本身不代表成功。

## 条件回流

| 发现节点与原因 | 下一动作 | 保留与失效范围 |
| --- | --- | --- |
| 03–06 发现范围内遗漏状态 | 回 02 登记，再进 03 | 已验证且无关联的状态保留 |
| 04 缺少可取得的证据 | 回 03 补采，再进 04 | 不以猜测代替证据 |
| 05 发现规格含糊或冲突 | 回 04；仍缺证据再回 03 | 暂停依赖该规格的实现 |
| 06 发现实现错误 | 05 定向修复 → 06 复测 | 重测修改影响的状态与共用依赖 |
| 06 发现规格误读 | 04 修正规格 → 05 → 06；缺依据则先 03 | 对旧规格的相关通过项失效 |
| 02–06 发现来源版本变化 | 回 01 核对，再由 02 计算受影响项 | 保留旧来源索引及必要差异，旧版本结论不直接继承 |
| 07 收尾OCR发现可核实问题 | 按原因回01/02/03/04/05，修复后经06再回07 | 保留审核报告；修复文件及关联检查重新验证，最终版本重新审核 |
| 任一节点无法取得必要证据、需要业务决定或达到停止条件 | 停止当前项，选择其他独立项；最终 07 partial | 不反复采集或生成，不删必需检查 |

## 恢复、回归与退出

恢复执行前比对来源、规格及原型摘要，从最早失效节点继续；未变化的工作项和证据复用，历史结果不覆盖。共用样式、组件或 Mock 修改后按依赖登记 affectedWorkItems，关联检查完成前不能沿用原通过结果。详细状态、计数及证据协议由[还原协议](../rules/prototype-reconstruction.md#循环记录与有效性)统一定义。

- completed：范围内工作项的全部适用必需检查和全局关联回归在当前摘要下通过，07收尾OCR通过或按协议证明无适用变更，没有未解决的阻断问题。not_applicable 必须有记录的适用性理由。
- partial：仍有失败、未验证、停止或阻塞项，来源/规格冲突未解决，或收尾OCR不可执行、覆盖不足、结果过期或存在未解决阻断问题；逐项写出原因、已完成部分及恢复所需条件。
- 同一原因连续两次修正仍失败时停止当前分支。无新增有效证据/变更的空转、单项执行上限和原有用户预算同样按协议处理，不能靠换问题编号或重启记录清零。

## 资产与结束条件

原型位于配置的 `project.prototypeRoot`，按功能维护；阶段、工作项与逐轮记录位于选定周期 `ui.root/reconstruction/`，共用 [记录模板](../template/ui/prototype-reconstruction.example.yaml)，不另建原型副本或 Execution Track。生成 Markdown 时遵循 [文档时间](../rules/document-timestamps.md)。独有截图、验证报告与必要局部差异在该周期 reconstruction 目录保存并由索引引用，不覆盖历史；不向 `.harness/evidence` 复制整份 PRD、原型或源码。每次实际原型修改追加既有 iterations，供 Gate 以记录路径#iteration-序号引用。

单阶段请求完成该阶段后结束。完整请求交付原型与分项验证记录；缺少运行页面时可以交付 `source-derived` 候选，必须保留视觉一致性 `not_verified`，不得声称完整还原。UI 确认按既有 [UI workflow](ui-design-workflow.md) 进入文档/确认阶段，不增加 Gate。来源变化只复跑受影响节点，不覆盖已有人工作品或重置其他角色状态。
