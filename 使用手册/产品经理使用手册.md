# 产品经理使用手册

- 手册版本：V1.0
- 适用基线：Atlas Core 0.35.0，配置 Schema 20
- 创建时间：`2026-09-11 18:18:26`
- 最后编辑时间：2026-09-22 18:37:14
- 时区：`Asia/Shanghai`


主线为 Mock → 生成或修订 PRD → 产品 Gate 确认，入口为 ../.harness/workflow/product-design-workflow.md。

1. Mock：先在需求周期 product/mock-changelog.md 记录本轮改动和 UI 规则依据，再修改项目根原型仓库，实际验证页面状态并记录反馈。
2. PRD：首次交付开始追踪，不表示封板。后续在原文上修改，每次通过 prd_revision.py 新增 CHG，记录原因、影响、局部 diff 与秒级时间，不保留全文副本。
3. Gate：进入产品确认后，检查当前交付并自动开展 grilling；必要修订完成后，由实际产品负责人确认最终内容，再更新根目录 Gate.yaml 的 product 记录，保存确认人、时间、范围和截至本次的变更引用。后续新增变更单独记账，按影响复核，旧确认不覆盖新改动。其他角色是否确认不构成前置。

原型是项目共用资产，不按需求周期建副本。产品不修改正式前端代码。产品反问内置于产品确认阶段，也可单独请求；PRD 增强、Word 导出、原型打包作为按需支线。仅要求生成、修改或导出 PRD，或打包原型时，完成指定任务后结束，不自动开始反问。

Mock 日志每次追加唯一 CHG 及可引用锚点；UI 调整和原型补建沿用各自的独立记录。封板不生成 `.harness/evidence` 产品快照，也不再生成 PRD 的 baseline/before/after 全文文件。实际 Git 提交保存完整历史，逐次变更日志不保证恢复每次未提交的中间全文。独有验证截图与报告按实际验证需要保存。

可直接要求“使用 package-prototype 技能，把当前项目的产品原型打包成 ZIP”。[原型打包技能](../.harness/skills/product/package-prototype.md)读取配置的原型目录，将全部内容压缩到同级文件，例如 `原型仓库/` → `原型仓库.zip`；同名包已存在时自动编号并保留旧包。无需先生成 PRD 或确认 Gate。

产品反问按决策依赖分轮展开：每轮提出全部前置条件明确的问题，每题附推荐答案；等待回答后再推进依赖这些答案的分支。输出采用 `❓ Q1 问题 / ➡️ 推荐答案` 形式，最终概括共同理解并等待负责人确认，不强制生成 PRD Review 或 PQ 表。共同理解确认不等于产品 Gate；后续已授权的 PRD 变更仍须逐次留痕。

同一内容已有可核实结论时复用，只补问未决或受业务变化影响的分支；跨会话缺少记录时先核对现有理解。没有待决问题时不凑题，直接准备最终确认。交付未变时，一次明确答复可同时确认共同理解和最终交付；有变化时先确认理解并修订，再确认修改后的内容。完整触发与复用规则见[产品确认技能](../.harness/skills/product/gate-confirm.md)。

示例任务：我负责产品，请为 v1.2 记录本轮 Mock 改动并依据 UI 规则更新项目原型，然后生成 PRD。已经存在的 PRD 请原位修订并逐次留痕。
