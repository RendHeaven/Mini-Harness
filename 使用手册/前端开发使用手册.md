本手册面向前端开发，用于页面规划、权限与复用、接口联调及测试养料。描述的是当前工作区能力，实际使用以项目锁定的 Core 原文为准。示例中的版本、路径和服务 ID 均需替换为真实值。

**你的职责：**将需求落入真实页面、路由、权限和接口调用，并提供可复核的工程证据。入口：[前端 Workflow](../.harness/workflow/frontend-workflow.md)。

## 开始前准备

确认 PRD、项目根静态原型及已消费变更引用、目标服务 ID、真实工程与 AGENTS、当前版本分支、已有组件/请求/权限机制以及结构化接口文档。UI Handoff、Dev Guide 有则交叉核对，缺少它们不阻止 UI 规划。每个服务分别建产物，默认根目录为 `develop/frontend/<service-id>/`。

## 按阶段使用

| 阶段 | 重点 | 主要产物 |
| --- | --- | --- |
| ui-plan | 按页面规划样式、交互、路由、权限及组件/逻辑复用，拆 TASK | `1-ui-plan/plan-overview.md`、每页一个 `plan-编号.md` |
| ui-exec | 将页面计划落入工程，核对复用方案并做构建、浏览器验证 | 每个已执行 Plan 对应 `2-ui-exec/exec-编号.md` |
| api-plan | 页面为一级结构，页面动作对应 TASK，核对真实接口 | `3-api-plan/plan.md` |
| api-exec | 真实联调，覆盖权限、异常、加载和状态变化 | `4-api-exec/task.md`、`exec.md` |
| Review | 独立检查产品、接口、代码及验证证据 | `5-review/review.md` |
| test-feed | 把页面、状态、权限、视觉和回归盲区交给 QA | `6-test-feed/front-feed.md` |

ui-plan 的页面边界示例：独立列表页和详情页各有一个 PLAN；附属弹窗通常放进所属页面。共享表格、Hook 或工具函数作为某页 TASK 或跨页依赖，不单独变成页面 PLAN。多个服务受影响时，每个服务分别规划、实现和验收。

涉及权限时，写清菜单/页面访问、按钮/行操作、数据或字段范围，以及有权限、无权限、直接访问受限路由、权限加载/失效的处理。权限码须来自真实工程或已确认契约；前端隐藏入口不能替代后端鉴权。

复用前先查现有代码，再选择直接复用、扩展、抽取共享或页面内新增，说明调用方影响和回归范围。不要只写“复用公共组件”，也不要仅因代码相似就强行抽取通用能力。

## 可复制指令

```text
我是前端开发，请为 v1.2 的<服务 ID>执行 ui-plan。
按页面拆分，每页覆盖样式、交互、路由、权限，以及组件和逻辑复用方案。
请先检索真实工程，列出复用来源、改动边界、TASK 和验收；本次先完成规划。
```

```text
请按已确认的 plan-01.md 执行 ui-exec，记录真实改动、构建和浏览器验证。
如复用假设与代码不符，先记录证据并回流计划，再调整相关 TASK。
```

```text
请为<服务 ID>执行 api-plan。
先按页面动作匹配后端结构化接口文档，未命中再检索真实后端及前端 service，
分类列出缺接口、缺请求字段、缺响应字段、缺语义和外部契约问题。
```

## Mock、交接与常见限制

需要本地模拟接口时，使用 [Mock Workflow](../.harness/workflow/frontend-mock-workflow.md)。可单独执行盘点、启动基建、数据、集成隔离或验证阶段；产物与 Runtime 位于前端服务仓库，例如 `docs/mock/` 与 `src/mocks/`。Mock 可以支持页面开发，不能代替真实联调或测试通过证据。

涉及页面时执行前端 UI 计划与实现；确实无页面改动才记录 uiStages=not-applicable 和 uiScopeReason，不使用产品/UI 代码作为跳过依据。

交给 QA 时提供 test-feed、页面与 REQ 映射、实际接口文档、验证 revision 和未解决问题。接口文档变化后重新检查受影响 API Plan、联调、Review、test-feed 与 TestHub 资产。
