本手册面向后端开发，用于方案、外部设计、TDD、实现、测试与接口文档。描述的是当前工作区能力，实际使用以项目锁定的 Core 原文为准。示例中的版本、路径和服务 ID 均需替换为真实值。

**你的职责：**完成可追溯的后端方案、实现、验证和准确接口文档。当前 Core 后端流程面向 Java 工程；其他技术栈须明确适配，不照搬 Maven/MockMvc 要求冒充验证。入口：[后端 Workflow](../.harness/workflow/backend-workflow.md)。

## 开始前准备

提供当前 PRD、项目根静态原型及已消费变更引用、Execution、服务 ID、真实源码与服务上下文，以及可读的表结构、契约、调用方和历史资料。Dev Guide、UI Handoff 是可选交叉核对输入。默认产物根目录为 `develop/backend/<service-id>/`。

| 阶段 | 你需要关注 | 主要产物 |
| --- | --- | --- |
| Plan | 业务边界、影响链路、技术取舍、TASK 与业务验收 | `1-plan/plan-overview.md`，多模块另有 `plan-NN-*.md` |
| 外部设计 | SQL、配置、权限、存储、消息、定时任务等适用设计 | `2-external-design/external-design.md` 及设计资产 |
| TDD | 实现前契约、测试骨架与基线引用 | `3-tdd/`；契约基线与测试代码在服务仓库 |
| Exec | 按 TASK 实现、单测与实际外部执行证据 | `4-exec/` 中总览及模块记录 |
| 本地接口测试 | 真实接口、边界、权限、异常和数据 | `5-local-interface-test/` |
| 接口文档 | 逐字段核对最终 Controller、DTO/VO、固定响应键 | `6-interface-document/api-document.md` |
| Review | 独立核对 Plan/TDD/Exec、REQ 与风险 | `7-review/` |
| 外部配置清单 | 尚待外部执行或审批的 SQL、Nacos、权限、MinIO | `8-checklist/checklist.md` |

后端按业务模块和交付风险拆分，不能把前端“每页一个 Plan”直接套到后端。模块 Plan、TDD、Exec、LocalTest 和 Review 需对应，不能用一个总览替代全部模块证据。

## 可复制指令

```text
我是后端开发，请为 v1.2 的<服务 ID>执行 Plan。
以当前 PRD 和真实调用链为依据，明确范围、复用方案、风险、TASK 与业务验收。
业务缺口登记 DEC，技术取舍登记 TDEC；本次不实现代码或执行数据库变更。
```

```text
Plan 已由<真实确认人/记录>确认，请按后端 workflow 完成外部设计和 TDD，
固定服务仓库契约基线及测试骨架。待实际前置条件具备后按 TASK 执行，
外部系统写操作按已有授权范围处理。
```

```text
请根据本期 Plan、TDD 和 Exec 生成结构化接口文档，
与最终 Controller、请求/响应模型及固定 Map 键逐字段对账，
明确前端消费点，不把设计中的字段写成已实现接口。
```

## 数据查询与交接

调查数据可以按[通用工具说明](通用工具与交接说明.md#database)使用项目 PostgreSQL 只读工具。数据模型、口径或调用链证据缺失时保留缺口；不能猜表结构、默认权限或计算规则。

交付前端的是最终结构化接口文档；TDD 设计基线不能替代它。LocalTest 是独立测试记录，不写成接口正文中的通过状态。SQL/Nacos 等详细设计与执行证据分别归档；外部配置 checklist 不放部署日志或泛化发布清单。需要 Jenkins 时参考[运维手册](运维与发布使用手册.md)，独立调用该能力。
