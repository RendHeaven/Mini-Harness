入口：[专项 workflow](../.harness/workflow/prototype-reconstruction-workflow.md)。主线版本：0.35.0 / Schema 20；正式使用以项目采用的精确 Core 为准。

示例指令：在当前项目执行已有页面原型补建，范围为指定模块，文档写入指定现有需求周期；读取对应前端源码，生成项目共用原型并验证，缺少运行基线时明确保留视觉核实缺口。

准备项目 Harness、目标页面/模块与可用运行入口；没有运行入口可先从源码开始。节点可单独调用，如“补充状态盘点”“重新验证图例与级数切换”。第一次补建不会覆盖历史原型或推断全部历史组件仍可达。

## 七节点怎样循环

完整执行时，01固定来源与范围，02将页面或区域与状态列成工作项。按依赖选择一项，执行03采证、04规格、05构建、06验证，再选择下一项。没有可运行项时，06汇总关联回归，07准备交付资料后执行open-code-review，再确定最终结果；审核问题回流修复后经06回归，再回07复核。具体路由以 [workflow 条件回流表](../.harness/workflow/prototype-reconstruction-workflow.md#条件回流)为准。

例如“列表筛选”验证失败：若实现与规格不符，回05修复再进06；若规格理解错误，回04，必要时03补证据；若发现遗漏的空态，回02登记该状态。其他无关联的已验证项保留，改到共用样式或Mock时复测所有受影响项。

可使用这样的指令：

> 按 prototype-reconstruction-workflow 完整补建当前模块。逐个处理页面状态，验证失败按原因回流；保留每轮证据和停止原因，最后交付入口及实际覆盖情况。

> 继续当前 reconstruction 记录中的未完成项。先检查来源、规格与文件摘要是否变化，重跑失效节点，复用有效证据，保留原失败次数。

> 本次只执行06验证，不自动修复；保存分项结果和建议回流节点。

## 记录与结束

模板使用 recordVersion 2，保存 loop、workItems、iterations、issues 和 regression；保存在既有周期的 ui.root/reconstruction/，原型仍在项目共用原型仓库。当前执行代理按这些指令推进并保存记录；YAML是执行记录，不是独立后台调度器，未安装或启动新的运行服务。

同根因连续两次修复后复测仍失败，停止该项；连续两次无有效进展或达到单项默认20次节点执行上限也停止。来源核对、盘点、全局回归与07收尾OCR另外累计默认20次上限与连续无进展次数，只有07保存现场和写报告免于重试上限。已知无法取得证据时直接记录缺口，其他独立项继续。不得通过改名或重启记录清零；这些上限在01固定，用户更严格的预算优先。

全部适用必需检查、关联回归与收尾OCR有效通过，或OCR有证据证明本轮没有适用变更，才可记录completed；证据缺失、依赖受阻、审核未完成或修复停止时交付partial。执行结束和验证通过分别记录，视觉未核实仍保留not_verified。单独请求01–06时执行完即结束；请求07时包含收尾审核，但审核发现的问题只记录建议，不自动扩大单阶段范围。

## 流程收尾的Open Code Review

审核覆盖从本轮开始基线到最终候选的全部原型改动，包含新增和未跟踪文件，不能只审最后一次修复。按[官方技能](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review/SKILL.md)选择CLI或官方委托模式，并保存原始结果、逐文件覆盖、问题及被审摘要。委托模式同样必须实际运行OCR的preview/rule，再由代理审核。

结果写入finalReview；工具不可用、文件被跳过、覆盖不足或结果过期时保持not_verified并说明恢复条件。零reviewable不能直接代表无问题。06提前评审不能替代此收尾步骤，源工程继承行为不自动修正；OCR根因须经修复复测和审核复核才关闭。

交付包含预览入口、来源与页面状态记录、本地演示数据说明、验证结果及未核实项。确认 UI 时沿用现有 UI Gate，不把本地预览或源码推断当作产品确认。
