本手册面向Atlas Core 维护者，用于维护团队流程、技能、规则、模板与校验能力。描述的是当前工作区能力，实际使用以项目锁定的 Core 原文为准。示例中的版本、路径和服务 ID 均需替换为真实值。

**你的职责：**维护当前协议与可复用能力，不保存具体项目业务事实。入口：[Core 说明](../.harness/README.md) 与 [Core 维护约定](../docs/core-maintenance.md)。

## 把变更放到正确位置

| 变更类型 | 位置 |
| --- | --- |
| 阶段编排和能力入口 | `.harness/workflow/` |
| 某阶段的输入、执行步骤与输出要求 | `.harness/skills/` |
| 跨阶段通用约束 | `.harness/rules/` |
| 项目接入、配置、hook 与工具脚手架 | `project-harness-template/` |
| 需求与研发产物模板 | `.harness/template/` |
| 确定性校验及测试 | `.harness/tools/` |
| 用户指引与维护约定 | `docs/`、`使用手册/` |

## 维护步骤

1. 明确本次问题、适用角色、影响及实施/推广范围，按团队 meta-harness Change 管理要求处理。
2. 修改权威来源，再同步入口、引用和模板；避免在多个 skill 复制相同规则。
3. 修改 Schema、模板字段或校验器时同步测试、版本锁与当前使用说明。仅文档调整按实际哈希覆盖范围判断是否需更新锁。
4. 当前版本由 `.harness/harness.yaml` 和 `.harness/version.lock` 持有，精确采用关联真实 Git revision。Core 仅维护当前用法，实施与采用过程由工作区治理记录持有。
5. 本地实现、自测、正式发布和项目采用分别记录。需要推广时明确消费者和精确提交，不自动修改所有项目。

可复制指令：

```text
请在 Atlas 中增加<通用能力>，适用角色为<角色>，范围为<阶段/模板>。
先核对现有流程与职责，实施必要的入口、规则/技能、模板和校验变更，
按范围验证并同步当前使用说明与版本锁。本次只修改 Core，不修改消费者或发布。
```

## 校验命令

以下命令在 Atlas 仓库根目录执行，使用可用 Python 环境和 `.harness/tools/requirements.txt` 声明的依赖。它们只调用校验器，不是部署命令。

```powershell
# Core 完整性；日常文案改动可选
python .harness/tools/validate_harness.py --core-only

# 修改 Schema、模板字段或校验器时，先做相应测试
python .harness/tools/test_validate_harness.py

# 正式项目校验；替换为真实项目路径和需求版本
python .harness/tools/validate_harness.py --project-root ../<项目Harness> .harness/demandCycle/<版本>
```

常规修改优先运行相关测试；发布、升 pin 或正式 Gate 按实际范围运行项目校验。`--allow-dirty-core` 仅用于明确的开发检查，不能作为正式发布锁或项目采用凭据。校验器输出不能替代浏览器、数据库、接口或部署的实际验证。
