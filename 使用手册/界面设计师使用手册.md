唯一主线为调整 → 生成调整文档 → UI Gate 确认。入口为 ../.harness/workflow/ui-design-workflow.md。

1. 读取 PRD、项目原型与 UI 规则，先记录调整内容，再修改根目录原型仓库，完成浏览器验证。
2. 汇总生成 ui/adjustments/UI-ADJ-*.md，更新 ui-handoff.md 的最新交付入口。
3. 实际 UI 负责人确认后更新 Gate.yaml 的 ui 记录，记录来源与时间。

产品和 UI 共用一份持续演进的原型，不按周期复制，不修改正式前端。不要求产品 Gate 先通过。涉及业务含义、权限、流程或验收时，先记录职责问题，主动询问用户按哪个角色处理；不自行切换角色或修改争议内容。

示例任务：我负责 UI，请按 UI 规则调整项目原型中的列表页面，先记录变化，再生成本轮调整文档。
