本手册面向运维 / 发布执行者，用于独立调用 Jenkins、分析日志、构建与部署验证。本角色通过独立 Jenkins skill 开展任务，不经 workflow 路由。描述的是当前工作区能力，实际使用以项目锁定的 Core 原文为准。示例中的版本、路径和服务 ID 均需替换为真实值。

**你的职责：**维护准确环境与发布约束，在授权范围内执行构建，确认真实部署结果。入口：[Jenkins skill](../.harness/skills/delivery/jenkins.md)。

Jenkins 是独立按需能力，不在任何 workflow 中编排，也不是研发阶段或 Gate。用户提出查询、日志分析或构建任务后，由能力入口或项目 AGENTS 直接加载该 skill。

## 首次接入

由项目维护者填写 [项目 Job 映射](../project-harness-template/.harness/projectContext/jenkins.md)，包含服务、环境、完整 Job、参数定义来源、审批和验证方式。Jenkinsfile 与部署清单仍在服务仓库，项目只记录引用。

按 [MCP 本地接入说明](../project-harness-template/.harness/tools/jenkins-mcp.md) 配置客户端与本机 Token 环境变量。模板不会自动注册连接。网关持有 Jenkins API Token，普通用户只使用 MCP Token。直接使用远端 MCP，无需另装 Jenkins Java/CLI/SDK；仍需可用客户端、网络与权限。

首次先调用 `whoami`，再查询目录、Job 及最近构建，完成只读验证。工具可见不代表服务端已允许构建；顶层 Folder 可见不代表可读子任务。

## 可复制指令

```text
请通过 Jenkins MCP 查询<完整 Folder/Job>最近一次构建，
固定具体编号后分析日志，给出首条可见致命错误、上下文和日志截断限制。
```

```text
请通过 Jenkins MCP 为<服务 ID>执行一次<环境>构建/部署。
完整 Job：<Folder/Job>；仓库：<引用>；分支/预期 revision：<目标>。
参数按真实 Job 定义核对：<已知参数及取值>。
本次授权范围：<影响范围及审批依据>；执行记录归属：<需求周期或运维记录目录>。
请关联本次触发回执与构建编号，返回构建结果、实际 revision、部署验证，
以及有证据支持的 NodePort/访问地址；缺失证据如实说明。
```

## 如何判断执行完成

- 提交、排队、运行中、构建终态和部署验证分别记录；并发情况下，不能把 `lastBuild` 当成本次构建。
- 触发超时或回执无法关联编号时先查证，不盲目重发。手册未列出 queue 查询工具，只有现场工具实际支持时才能使用相应能力。
- 等待有上限，到时返回真实状态与编号；没有另外安排就不意味着持续后台监控。
- Jenkins `SUCCESS` 不等于服务可用。核对实际版本、目标环境及项目健康/业务检查后，才能说明部署验证结果。
- NodePort 和访问地址来自本次日志、部署产物或授权环境查询；无依据标为 `unverified`，不能从 MCP 网关地址推算。

使用 [Jenkins 执行模板](../.harness/template/develop/delivery/jenkins-execution-template.md) 按次记录，默认位于周期 `develop/delivery/<service-id>/`。生产审批遵守项目实际流程，Review/Gate 不替代发布授权。

被 `ALLOWED_JOBS`、Jenkins 权限或 `ENABLE_BUILD` 拒绝时交由管理员处理；不改用直接 API、Replay 或配置修改绕过边界。
