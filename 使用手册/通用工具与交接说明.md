## PostgreSQL 只读查询

适用于后端调研、QA 数据核对或授权排障。项目采用工具后，安装可用 uv；首次运行由 uv 准备 Python 与内联依赖，缓存缺失时需要下载网络。本机 `.harness/tools/.env.local` 分别保存地址、端口、库名、账号和密码，只读账号由数据库管理方提供。

仅首次从 `.env.example` 准备本地配置，已有文件不要覆盖。真实配置不入库、不贴到聊天或日志。工具使用本地文件配置，不以数据库环境变量或命令行账号参数覆盖。

在项目 Harness 根目录可执行：

```powershell
# 查看帮助，不连接数据库
uv run .harness/tools/db_tool.py --help

# 检查已授权数据库连接，执行 SELECT 1
uv run .harness/tools/db_tool.py check

# 只读查询示例
uv run .harness/tools/db_tool.py query --sql "SELECT current_date AS today" --format json
```

完整参数、超时和上限见 [数据库工具说明](../project-harness-template/.harness/tools/README.md)。该工具不用于执行 DDL、迁移或修复数据；SQL 预检查及只读事务不能替代数据库权限配置。输出行数上限不等于数据库扫描上限。

## 跨角色交接清单

每次交接至少给出以下信息，放到对应阶段产物或回复中，不另造一套状态文件：

| 信息 | 应明确什么 |
| --- | --- |
| 身份与范围 | 项目、需求版本、服务 ID、REQ/TASK/Bug |
| 当前来源 | PRD/原型路径及已消费变更引用，计划/接口文档路径，以及工程证据所需的哈希和代码 revision |
| 交付内容 | 可打开的文件、代码位置、分支及真实提交/推送状态 |
| 验证证据 | 实际执行了什么，什么通过、失败、未执行或受环境阻塞 |
| 待办与责任 | 产品决策、技术决策、缺口、负责人及下一步 |

研发到 TestHub 的 Markdown 产物保留创建时间、最后编辑时间和逐次编辑记录，精确到秒，时区为 `Asia/Shanghai`。REQ 等稳定 ID 不因排序或标题变化而重编号。

## 常见问题

| 情况 | 应如何处理 |
| --- | --- |
| 不知道先进入哪个阶段 | 提供角色、需求版本与本次目标，让助手读取项目及 workflow 后定位 |
| 找不到 Core 或 pin 不一致 | 由项目维护者确认 checkout 或升级，不擅自改 pin |
| 没有 UI Handoff / Dev Guide | 前后端可基于 PRD、项目静态原型和真实工程继续；UI 按自身输入要求记录缺口 |
| 接口尚未满足前端需求 | 先查结构化文档，再查真实实现，分类记录契约缺口并回流 |
| 没有真实环境 | 推进有依据的计划、代码或用例工作，实际验证保持未执行/blocked |
| 产品规则在实现时变化 | 记录争议与影响，主动询问用户按哪个角色处理；答复前不修改争议事实，不自动切换流程 |
| TestHub 同步成功但没有测试结果 | 显式发起 Run，并检查本次 run_id 的启动状态与终态 |
| Jenkins 已 SUCCESS 但访问失败 | 查询准确构建、核对部署版本与健康/业务检查，不直接认定部署成功 |
| 修复了 Bug 但只有未提交代码 | 保留真实状态，完成服务提交及验证证据后再按 Bugfix 协议交付 |
| Gate 通过但还有告警 | 按真实问题跟进；通过只表示检查已完成，不消除风险或实际阻塞 |
